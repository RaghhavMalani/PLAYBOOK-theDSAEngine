Why this is the highest-value tool here. "Fails on hidden test 7" is unactionable. This finds the disagreement, then shrinks it — halving the input, dropping single elements, pulling values toward zero — until you have the smallest case that still fails. A 500-element failure becomes [-1], and a 500-element failure you cannot debug becomes a two-minute fix. Every competitive programmer does this; almost no interview prep teaches it.

measured growth · log–log
What this does that a code review cannot: it does not infer your complexity from the shape of your loops — it measures it. Your function is timed at n = 400 … 12800 and a log–log regression recovers the empirical exponent. Slope 1.0 is linear, 2.0 quadratic, ~1.1 with curvature is n log n.

It measures wall-clock time on purpose. Counting executed lines would be tidier but it lies: x in some_list is a single line hiding an O(n) scan, and sorted() is a single line hiding all of the work. Timing sees straight through to the real cost — which is exactly where hidden quadratics live.

Caveat worth knowing: browsers coarsen their clock for security, so tiny inputs are repeated automatically until each measurement is long enough to trust. Very fast functions will still show noise at the smallest sizes.
